## 6.1.9 升级（2026-09-18，当前基准）

后续开发均以 **6.1 为基准**。本次从 0.10.7 升级到 Spatial BOM `6.1.9`
（设备运行时为 6.1.0），并在 6.1 模拟器（Android 16 / API 36）完成 2D+3D 全链路验证。

| 项目 | 升级后 |

| Kotlin | `2.0.21`（改用 `org.jetbrains.kotlin.plugin.compose`） |
| compileSdk / targetSdk | `36` |

| versionCode / versionName | `2` / `6.1.9` |
| 资源打包 | `noCompress` 增加 `.glb/.ktx/.usdz/.bundle` |

源码迁移点（仅 `HomePanel.kt`）：

- 6.1 的 `Text` 已无 `vibrant=` 参数，Vibrant 文字改为
  `modifier = Modifier.vibrantEffect(Vibrant.X)`。
- `PicoTheme.colorScheme.accent` 已移除，按钮色改用
  `PicoTheme.colorScheme.fillPrimary`（6.1 的 colorScheme 字段直接是 `Color`）。

世界锁定与窗口修复：

- Stage 改为 `openStage(STAGE_ID, StageStyle.Full)` +
  `Immersion(default=100, min=0, max=100)`：进入即按脚底原点建立世界坐标，房间世界锁定；
  Mixed 依赖真机空间追踪，模拟器无参考系会半跟随头部。
- Home 的 WindowContainer `worldscaletype` 从 `2`（Fixed）改为 `1`（Dynamic）：
  Fixed 下窗口实际尺寸固定、被系统放远后又小又远；Dynamic 保持恒定视觉大小。

验证证据（emulator-5554，`Pico_Emulator_6_1`）：

- uiautomator 取得“进入房间”真实可点区域 `[1064,849][1336,945]`，中心 `(1200,897)`。
- Stage `HOTLINE_CHAMBER`：`type=stage, stageStyle=3, immersion=100, life=foreground, focus=true`；
  `space_status` 由 `sharedspace` 变为 `fullspace`。
- 4 个 GLB 全部加载：`场景就位: 前向偏移 z=-3.0，可交互 3 个，失败 0 个`。
- Watchdog `focus=6(...hotlinechamber)` 渲染心跳持续；无 FATAL、entity invalid、signal 9。
- BACK 后 Stage `life=destroyed`，Home 面板恢复。Stage 打开时保留 Home 容器属官方标准模式
  （关闭 Stage 后返回），模拟器合成截图中的文字叠显不代表故障。

## 构建与日常操作

在 `HotlineChamberSpatial` 目录运行：

```bash
JAVA_HOME="/Applications/Android Studio Preview.app/Contents/jbr/Contents/Home" \
  ./gradlew :app:assembleDebug
```

已实测构建通过（`BUILD SUCCESSFUL`），APK 位于
`app/build/outputs/apk/debug/app-debug.apk`。本次构建命中已有任务缓存，未执行 clean。
Luna 子代理还验证了 `env -u JAVA_HOME ./gradlew :app:assembleDebug --offline --console=plain`
成功，因此本机可直接执行 `./gradlew :app:assembleDebug`。

## 模拟器与安装验证

```bash
# 交互 zsh 会读取 ~/.zshrc；非交互自动化必须显式设置
export PICO_HOME="$HOME/Library/PICO/sdk"
export PICO_EMULATOR_HOME="$PICO_HOME/6.1/emulator"
pico-cli emulator list --format json
pico-cli emulator start --avd Pico_Emulator_6_1 --bundle-version 6.1.0 --format json
pico-cli shell --device emulator-5554 getprop sys.boot_completed
pico-cli app install app/build/outputs/apk/debug/app-debug.apk --device emulator-5554 --replace
pico-cli app launch com.pico.spatial.sample.hotlinechamber \
  --activity .platform.LaunchActivity --device emulator-5554
```

设备编号以 `pico-cli device list --format json` 当前输出为准。本次新实例复用了旧实例曾用的
`emulator-5554` 编号，所以还需核对 AVD、QEMU 路径与 guest 版本，不能只凭 serial 判断版本。

本次安装器返回 `Installed PICO Emulator 6.1.0`；新 AVD 启动返回 `bootCompleted=true`、
`startupStatus=ready`。QEMU PID `54340` 的真实可执行路径来自 `sdk/6.1/emulator/qemu/`。
guest `vendor.qemu.version=6.1.0`，Spatial Runtime 为 `6.1.0.0-rls.24`。
APK 安装返回 `Success`，启动命令成功，应用 PID `4804`。设备 crash buffer 无输出；
普通日志仍有 MESA/rendernode 和平台 E 级输出，不宣称运行日志全无错误。
Watchdog focus 为本应用，`lastRenderTime` 从 `121795` 持续增加至 `203180`，
确认启动窗口持续渲染。

尚未验证在空间窗口中点击“进入房间”后的 Stage 与四个模型加载；这一步需要模拟器
空间输入或人工操作，不能由进程存活推断成功。

## 已固化的排坑修复

create 再次触发安装。指定 `PICO_EMULATOR_HOME` 为 6.1 bundle 后解决；仅把版本参数
从 `6.1` 改为 `6.1.0` 无效。不要更改 bundle 版本元数据或把 PICO_HOME 永久改到版本子目录。
